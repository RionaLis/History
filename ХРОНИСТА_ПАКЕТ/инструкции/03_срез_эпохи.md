# ШАГ 03. Паспорт эпохи и срез данных

Здесь эпоха превращается из замысла в набор файлов. Два действия: написать
`era.yml` и запустить `extract_era.py`.

Занимает от 30 секунд (если эпоха уже есть) до получаса (написание списка
`expected` для новой эпохи). Сам срез идёт 30 секунд — 3 минуты.

---

## 1. Создать папку эпохи

```bash
cd ~/history-demo
cp -r maps/eras/_template maps/eras/rome117
```

Имя папки — латиницей, без пробелов. Оно станет именем тайла:
`tiles/era-rome117.pmtiles`. Дальше везде используется как аргумент команд.

---

## 2. Заполнить era.yml

```bash
nano maps/eras/rome117/era.yml
```

Минимально необходимый набор полей:

```yaml
id: rome117                        # = имя папки
name_ru: "Римская империя в 117 году н. э."
name_short_ru: "117 н. э."

year: 117                          # отрицательное = до нашей эры
valid_from: 115                    # окно эпохи
valid_to: 119

scope: world                       # мировая эпоха
ohm_planet: "~/ohm/planet-261022_0000.osm.pbf"
maxzoom: 6                         # мировой снимок: 5–6
```

### 2.1. Про `year` и окно

`year` — точка эпохи. `valid_from`/`valid_to` — окно, объекты вне которого
не попадут на карту. Если окно не задать, оно возьмётся из `era.yml` как
половина от `valid_to − valid_from`.

Переопределить с командной строки:

```bash
python3 tools/extract_era.py ohm rome117 --overpass --window 150
```

Шире окно → больше объектов, но и больше «почти подходящих». Для −2400 года
до н. э. окно ±50 даёт слишком скудную картину, ±150 — рабочую.

### 2.2. Про `bbox` — НЕ задавайте её для мировой карты

```yaml
scope: world
# bbox — НЕ ЗАПОЛНЯЕМ
```

`bbox` нужна **только** для прицельного регионального фрагмента. Для мировой
карты она вредна, и это проверено на ваших же данных:

* с рамкой 20,5,78,42 из среза −2400 выпадали **культура колоколовидных
  кубков** (Испания) и **Аван**; когда рамку сняли, они нашлись — пропусков
  стало **6 вместо 8**;
* срез 117 года с рамкой дал 56 государств, без рамки — **75**: добавились
  Парфия (Q1986139), Аксум (Q139377), Лузитания, Бетика, Сицилия, Далмация,
  Паннония, Тарраконская Испания, Теотиуакан, Moche, Paracas, Monte Albán,
  ханьские командорства 樂浪郡 и 玄菟郡.

**Мировой срез не тяжелее регионального.** Замерено: срез 117 года на всю
Землю проходит за **29 секунд** и не падает по памяти. Память убивает запрос
**без фильтра по дате**, а не запрос без рамки: в одной рамке 20,5,78,42 лежит
42 116 отношений `boundary=*` за все эпохи сразу — вот это и был обрыв
процесса с кодом 137. Числовой фильтр по дате режет срез до 45 объектов
независимо от географии.

Если всё же нужен регион:

```yaml
scope: mediterranean
bbox: [-12, 22, 62, 60]            # запад, юг, восток, север
```

Рамку делайте **шире** самого региона: культуры и торговые пути заходят за
его пределы.

### 2.3. Про `maxzoom`

Это единственный реальный рычаг веса тайла. Замерено на эпохе bc323
(88 объектов, 13 916 вершин, 321 КБ GeoJSON):

| maxzoom | Вес тайла |
|---:|---:|
| z0–4 | 175 КБ |
| z0–5 | 335 КБ |
| **z0–6** | **692 КБ** |
| z0–7 | 1 486 КБ |
| z0–8 | 3 325 КБ |

Дальше z6 для мирового снимка смысла нет: деталь всё равно другая. Архитектура
такая — **мировой снимок на z0–6** плюс отдельные региональные файлы
`maps/poi/rome/` на z10–14 для уровня Колизея. Не пытайтесь впихнуть деталь
Рима в мировой тайл: вес вырастет на порядок.

> `setPixelTolerance` и прочие настройки упрощения геометрии дают выигрыш
> не более 11%. Не тратьте на них время — только `maxzoom`.

## 3. Список `expected` — единственное, что нельзя автоматизировать

Инструмент не может догадаться, чего в данных **нет**. Поэтому вы пишете
список того, что обязано быть на карте этой эпохи, и срез сверяется с ним.

```yaml
expected:
  - {ru: "Римская империя",   variants: ["Imperium Romanum", "Roman Empire", "Regnum Romanum", "Roma"]}
  - {ru: "Парфия",            variants: ["Parthia", "Parthian Empire", "Arsacid"]}
  - {ru: "Александрия",       variants: ["Alexandria", "Alexandria Aegypti"]}
  - {ru: "Аппиева дорога",    variants: ["Via Appia"]}
  - {ru: "Аппиев акведук",    variants: ["Aqua Appia"]}
```

Правила:

**Варианты написания обязательны.** В OHM Римская империя может лежать как
«Regnum Romanum», «Imperium Romanum» или «Roman Empire». Без вариантов
объект найдётся, а в отчёт попадёт как отсутствующий.

**`variants` — это список.** Замеренная ошибка отладки: наивное сравнение
`str(v).lower()` давало строку `"['Kulli']"` вместо `"kulli"`, и сопоставление
молча не срабатывало — 13 реально отсутствующих объектов превращались в 8.

**Q-номера здесь не проставляйте.** Их надо проверять через
`tools/wd_lookup.py`, а не писать по памяти. Я взял однажды Q189058 для
Гавгамел — это оказался Целлинген в Баварии.

### Как это работает на практике

В шаблоне 117 года 44 записи `expected`. Реальный результат мирового среза:

```
НЕ найдено из ожидаемого: 10
- ✗ Иудея
- ✗ Месопотамия
- ✗ Кушанское царство
- ✗ Сарматы
- ✗ Албания Кавказская
- ✗ Иерусалим
- ✗ Пергам
- ✗ Эгнатиева дорога
- ✗ Янтарный путь
- ✗ Великий шёлковый путь
```

Это и есть ваш список ручной работы: десять объектов, которых в OHM нет и
которые придётся нарисовать самому. Без `expected` вы бы о них не узнали —
карта выглядела бы полной.

Для −2400 года до н. э. из 20 записей не нашлось 6: Ур, Аккад, Аратта,
Мархаши, Гутиум, амореи. Все шесть в OHM действительно отсутствуют —
проверено прямым запросом по именам.

## 4. Запустить срез

```bash
cd ~/history-demo
python3 tools/extract_era.py ohm rome117 --overpass
```

* `--overpass` — брать данные через API. Если у вас скачан дамп планеты и
  путь к нему прописан в `era.yml`, флаг можно не давать: тогда срез пойдёт
  через `osmium`, что быстрее и не зависит от доступности сервера OHM.
* `--force` — пересобрать заново, игнорируя кэш.
* `--window 150` — переопределить окно.
* `--bbox З,Ю,В,С` — переопределить рамку (для мировой карты не нужно).

Реальный вывод мирового среза 117 года:


```
maps/eras/rome117/
├── era.yml                     паспорт
├── polities.auto.csv    75     заготовка таблицы государств
├── cultures.auto.csv     3     заготовка таблицы культур
├── places.auto.csv    1525     заготовка таблицы городов
├── routes.auto.csv       5     заготовка таблицы путей
├── geom/
│   ├── hydro.geojson    645    реки и озёра эпохи + подложка Natural Earth
│   ├── borders.geojson          геометрия границ
│   └── …                        по файлу на слой
└── qgis/
    ├── borders.geojson   75    слои для открытия в QGIS
    ├── cultures.geojson
    ├── places.geojson
    ├── routes.geojson
    ├── hydro.geojson
    ├── gaps.md                 отчёт: что сомнительно и чего не хватает
    └── открыть_в_qgis.sh
```

### Почему `.auto.csv`, а не `.csv`

Файлы с суффиксом `.auto.csv` **перезаписываются при каждом запуске**. Ваши
правки живут в файлах без суффикса. Скопировать заготовку в рабочий файл:

```bash
for f in polities cultures places routes; do
  cp maps/eras/rome117/$f.auto.csv maps/eras/rome117/$f.csv
done
```

Сборка карты читает именно `polities.csv`, `cultures.csv`, `places.csv`,
`routes.csv`. Это общее правило всего проекта.

## 6. Отчёт gaps.md

Главный результат шага — не файлы, а отчёт. Он отвечает на два вопроса:
**что сомнительно** и **чего не хватает**.

```bash
less maps/eras/rome117/qgis/gaps.md
```

Структура отчёта:

| Раздел | Что там |
|---|---|
| Не найдено из ожидаемого | Ваш список ручной работы |
| Объекты, требующие решения | Каждый с причиной, почему он помечен |
| Пересечения по времени | Объекты одного типа с пересекающимися годами — подозрение на ошибку |
| Дубли | Один объект под разными id (хронология OHM) |
| Отброшено автоматически | Что и почему не попало в срез |
| Качество датировок | Объекты с `start_date:fixme=arbitrary` и подобным |

## 7. Про кэш и доступность OHM

OHM Overpass находится **за Cloudflare**, и под нагрузкой отдаёт HTML-страницу
с кодом **200** и заголовком `Content-Type: application/json`. Это выглядит
как битый ответ парсера, но на самом деле запрос не выполнен.

Поэтому в `extract_era.py`:

* **6 попыток** с ожиданием 60, 120, 180, 240, 300 секунд;
* **кэш успешных ответов** в `maps/_cache/overpass/` — повторный запуск той же
  эпохи не трогает API вовсе;
* не-JSON-тела сохраняются на диск, чтобы можно было посмотреть, что пришло;
* отдельная проверка на Cloudflare-HTML.

Ещё одна грабля, найденная при отладке: **клиентский таймаут не отменяет
запрос на сервере**. Сервер продолжает его считать, и следующая попытка сразу
упирается в лимит 2 одновременных запроса. Отсюда длинные паузы — они не
паранойя.

Реальная скорость с кэшем: повторный срез 117 года — **4 секунды** вместо
29. Без кэша и при занятом сервере — до 10 минут с повторами.

## 8. Что срез находит, а что нет

Замерено на двух мировых эпохах:

| Слой | −2400 до н. э. | 117 н. э. | Откуда |
|---|---:|---:|---|
| Государства | 9 | 75 | OHM `boundary=administrative` |
| Культуры и народы | 12 | 3 | OHM, определяется эвристически |
| Города и памятники | 196 | 1527 | OHM `place=*`, `historic=*` |
| Пути | 0 | 5 | OHM `route=*` |
| Миграции | 0 | 0 | **в OHM нет такого значения** |
| Реки эпохи | 8 | 45 | OHM, только именованные |

### Важное про археологические культуры

**В OHM нет отдельного тега для археологических культур.** Замерено:
`Bell Beaker culture`, `Arzachena culture`, `Kulli culture`, `小珠山文化`,
`Indus Valley Civilisation` — все они лежат как `boundary=administrative` +
`admin_level=2`, то есть неотличимы от государств вроде Элама или Кемета.

Слабые признаки, по которым инструмент пытается их опознать:
`border_type=kingdom` (есть у одного объекта — Regnum Romanum),
`country=部落` («племя», на объекте 小珠山文化), и слова в самом `name`.

Поэтому **каждая культура помечается как догадка**, и тип `kind=culture` в
отчёте всегда сопровождается причиной. Перепись всех 82 539 отношений
`boundary=*` в OHM подтверждает: значений `route`, `trade_route`, `migration`
там нет вообще — пути переселений придётся рисовать вручную.

### Важное про качество дат

Замерено на мировом срезе 117 года, по кэшу Overpass:

| Файл | Пометка | Штук |
|---|---|---:|
| `hydro_117.json` | `start_date:fixme = arbitrary` | **120 из 210 (57%)** |
| `hydro_117.json` | `fixme = arbitrary end_date` | 43 |
| `areas_117.json` | `start_date:fixme = arbitrary` | 34 |
| `points_117.json` | `fixme = Exact start and end dates` | 122 |
| `points_117.json` | `fixme = Location is estimation…` (Ohlone) | 57 |
| `points_117.json` | то же про Coast Miwok | 37 |

Слово `arbitrary` в OHM означает буквально «произвольно»: дату поставили,
чтобы объект попадал в срезы, а не потому, что она известна. Все такие
объекты помечаются в поле `gap` и попадают в отчёт.

## 9. Учебный полигон OHM — filter `testbed`

В базе OHM есть **277 объектов** с тегом `testbed=yes` (56 узлов, 220 путей,
1 отношение). Это учебные данные, а не история. Выглядят они безобидно и
потому опасны:

```
way/198794205   boundary=administrative  admin_level=9  start_date=0020-02-28
                name=«Admin 9 9999999 Admin 9»           testbed=yes
way/198794253   boundary=administrative  admin_level=3  start_date=0020-02-28
                name=«3 Admin 3 3333333 Admin 3»         testbed=yes
                name:ru=«OHM содержит исторические данные»
                + ещё 200 с лишним тегов name:* с переводом этой фразы
```

Дата `0020-02-28` честно попадает в срез 117 года, поэтому фильтр по времени
их пропускает. В мировом срезе их оказалось **34 из 2324 элементов** (1,5%),
и они заняли верх таблицы государств, вытеснив настоящие провинции.

Отсекаются тегом `["testbed"!~"."]` и в запросе, и в Python на пути через
дампа планеты. После фильтра государств стало 75 вместо 85, мусора ноль.

> **Именно этот тег, а не географическая рамка, защищает срез от мусора.**
> Это вторая причина, по которой `bbox` для мировой карты не нужна.
