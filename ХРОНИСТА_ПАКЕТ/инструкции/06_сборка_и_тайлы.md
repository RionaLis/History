# ШАГ 06. Проверка, сборка и нарезка тайлов

Три команды. Занимает от 40 секунд (одна эпоха) до двух минут (все эпохи).

```bash
cd ~/history-demo
python3 tools/validate_map.py rome117
python3 tools/build_map.py era rome117
python3 tools/make_tiles.py
```

## 1. Проверка — validate_map.py

```bash
python3 tools/validate_map.py rome117
```

Ожидаемый результат:

```
ЭПОХА: rome117   ✓ ошибок нет
ИТОГ: ошибок нет. Предупреждения (!) — это список дел, не блокировка.
```

Все эпохи сразу:

```bash
for e in bc2400 rome117 bc323; do
  printf "  %-9s " "$e"; python3 tools/validate_map.py "$e" 2>&1 | grep -E "^ИТОГ"
done
```

### Что считается ошибкой, а что предупреждением

| | Ошибка (✗) — блокирует | Предупреждение (!) — список дел |
|---|---|---|
| Координаты | вне диапазона −180…180, −90…90 | |
| Обязательные поля | пустые `lon`/`lat` в точечных файлах | |
| Q-номер | не похож на `Q…` | **пустой** — сборка работает, но объект не свяжется со статьёй |
| Дубли Q-номера | повторяется в пределах файла | |
| `kind` | | **не из известного списка** — сайт возьмёт запасную иконку |
| Геометрия | | не найдена для строки таблицы |
| Вершины | | больше 400 000 — прогоните через mapshaper.org |
| Без имени | | «серые пятна» — объект нарисуется, но подписи не будет |

> **Почему пустой `wikidata` — предупреждение, а не ошибка.** В данных OHM
> wikidata нет у очень многих объектов: на срезе −2400 года из 6 государств
> его не было у 3 (Inebu-hedj, Khepesh, Kemet/Древнее царство). Блокировать на
> этом сборку — значит не собрать вообще ничего. Но для платного продукта это
> всё равно надо закрыть: без Q-номера объект не связать ни со статьёй, ни с
> внешним источником.

### Ошибки, которые валидатор ловил на реальных данных

**`kind «label» недопустим`** — 29 ошибок на корректном мировом срезе 117 года.
Причина была в валидаторе, а не в данных: я добавлял новые типы в
`extract_era.py`, а список допустимых оставался старым. Исправлено: свои
наборы для каждого файла, см. шаг 05, §B5.

**`kind «битва» недопустим`** — 6 ошибок на `events.csv`, где лежали «битва»,
«персона», «катастрофа». Валидатор проверял события по списку типов **мест**.
У событий свой словарь, и он открытый.

**`нет ни geom/Q927198.geojson, ни geom/all.geojson`** — Londinium попал в
границы точкой. Исправлено в `extract_era.py`: тип геометрии проверяется
раньше тега `boundary`.

## 2. Сборка — build_map.py

```bash
python3 tools/build_map.py era rome117
```

Реальный вывод:

```
  ✓ rome117: 9,401 КБ → out/era-rome117.geojson
      границы по таблице: 74   не опознано (серым): 0   без геометрии: 2
      города: 1527   события: 0   морские бои: 9
```

Все эпохи:

```bash
python3 tools/build_map.py era --all
```

### Что читает сборка

| Файл эпохи | Слой в результате |
|---|---|
| `polities.csv` + `geom/` | `borders` |
| `cultures.csv` + `geom/` | `cultures` |
| `routes.csv` + `geom/` | `routes` |
| `geom/hydro.geojson` | `hydro` |
| `places.csv` | `places` |
| `sea_battles.csv` | `battles` |
| `geom/epidemics.geojson` | `epidemics` |
| `events.csv` | `events` |

Файлы `.auto.csv` сборка **не читает** — только рабочие, без суффикса.
Если вы забыли скопировать заготовку, слой окажется пустым, и это не ошибка
программы:

```bash
for f in polities cultures places routes; do
  cp maps/eras/rome117/$f.auto.csv maps/eras/rome117/$f.csv
done
cp maps/eras/rome117/sea_battles.auto.csv maps/eras/rome117/sea_battles.csv
```

### Как геометрия находится для строки таблицы

Три способа, проверяются по порядку:

1. `geom/<wikidata>.geojson` — **личный файл на объект**. Положите полигон в
   `geom/Q128904.geojson` и напишите `Q128904` в колонку `wikidata`.
2. `geom/<значение колонки geom>.geojson` — имя задаёте вы.
3. `geom/all.geojson` — общий файл, сопоставление по колонке `match`.

Если ничего не найдено, объект попадает в счётчик «без геометрии» и в
предупреждения валидатора.

### Про `hist_names_all`

Сборка **выбрасывает** из тайла три поля, нужных только для проверки:
`hist_names_all`, `hist_modern_ru`, `hist_note`, и урезает `hist_candidates`
до четырёх вариантов. Причина — вес: замерено, что с ними
`era-rome117.pmtiles` занимает 3,85 МБ вместо 2,54 МБ. Полный список остаётся
в `geom/hydro.geojson` и в отчёте `qgis/названия_водоёмов.md`.

## 4. Проверить готовый тайл

Это стоит делать всегда: файл может собраться без ошибок и оказаться пустым.

```bash
python3 - <<'PY'
import gzip, collections, os
from pmtiles.reader import Reader, MmapSource

for name in sorted(os.listdir('tiles')):
    if not name.endswith('.pmtiles'):
        continue
    path = 'tiles/' + name
    with open(path, 'rb') as f:
        r = Reader(MmapSource(f)); h = r.header()
        vl = sorted(v['id'] for v in r.metadata().get('vector_layers', []))
        c = collections.Counter(); tiles = 0
        for z in range(h['min_zoom'], h['max_zoom'] + 1):
            for x in range(2 ** z):
                for y in range(2 ** z):
                    d = r.get(z, x, y)
                    if not d:
                        continue
                    tiles += 1
                    try:
                        d = gzip.decompress(d)
                    except Exception:
                        pass
                    for n in (b'borders', b'cultures', b'places', b'events',
                              b'routes', b'hydro', b'battles', b'epidemics'):
                        if n in d:
                            c[n.decode()] += 1
        print(f'  {name:24s} {os.path.getsize(path)/1024:7.0f} КБ '
              f'z{h["min_zoom"]}–{h["max_zoom"]} тайлов {tiles:5d}')
        print(f'      объявлено: {vl}')
        print(f'      реально:   {sorted(c)}')
        if set(vl) != set(c):
            print(f'      ! РАСХОЖДЕНИЕ: объявлено не то, что лежит в тайлах')
PY
```

Реальный результат:

```
  era-bc2400.pmtiles          573 КБ z0–5 тайлов   346
      объявлено: ['borders', 'cultures', 'hydro', 'places']
      реально:   ['borders', 'cultures', 'hydro', 'places']
  era-rome117.pmtiles        2598 КБ z0–6 тайлов   992
      объявлено: ['battles', 'borders', 'cultures', 'hydro', 'places', 'routes']
      реально:   ['battles', 'borders', 'cultures', 'hydro', 'places', 'routes']
```

**Сверяйте «объявлено» и «реально».** На демо-эпохе bc323 они расходились:
объявлено три слоя, а в тайлах четыре — культуры лежали в данных, но не были
описаны в метаданных, и часть клиентов их из-за этого не показывала.

## 5. Что запечено в тайл

`ChronoProfile.java` копирует в тайл **все** свойства объекта, кроме тех, что
начинаются с `_`. Поэтому новое поле появляется в тайле само, править профиль
не нужно. Служебные поля (`_layer`, `_place`, `_historic`) используются для
раскладки по слоям и в тайл не попадают.

Поля слоя `hydro` в тайле 117 года (37 штук), исторические среди них:

```
hist_candidates   hist_label   hist_match   hist_name
hist_qid_clash    hist_source  hist_wikidata
```

Проверено чтением тайла: строка «Понт Эвксинский» присутствует в данных
`era-rome117.pmtiles` и находится уже в тайле z0/0/0.

## 6. Грабли нарезки

**Точки надо выпускать через `features.point()`, а не через
`features.anyGeometry()`.** Проверено на Planetiler v0.10.2: на GeoJSON из
ОДНОЙ точки `anyGeometry()` не выдаёт ничего — в `.pmtiles` оказывается
`vector_layers: []` и ни одного тайла. Тот же файл через `point()` +
`setMinZoom(0)` даёт слой и тайл весом 102 байта.

Симптом очень тихий: сборка проходит без ошибок и предупреждений, вес файла
выглядит правдоподобно (полигоны-то на месте), а города и события на карте
просто не появляются. Именно так в демо-эпохе bc323 пропали 2 города и
5 событий, а в bc2400 — все 196 городов.

**`javac` печатает «error while writing NullProfile: null»** — это не ошибка,
а особенность сборки профиля. На результат не влияет.

**Папка с Java не должна начинаться с точки.** Однажды я скачал JDK в `~/.jdk`,
и она исчезла между сессиями: каталоги, начинающиеся с точки, исключаются из
сохраняемого снимка рабочей области. Держите JDK в `~/jdk21` или ставьте через
`apt`.

## 7. Вес: что на него влияет

Замеры на эпохе bc323 (88 объектов, 13 916 вершин, 321 КБ GeoJSON):

| maxzoom | Вес |
|---:|---:|
| z0–4 | 175 КБ |
| z0–5 | 335 КБ |
| z0–6 | 692 КБ |
| z0–7 | 1 486 КБ |
| z0–8 | 3 325 КБ |

| Фактор | Влияние |
|---|---|
| `maxzoom` | **единственный реальный рычаг**: ×2 на каждый зум |
| `setPixelTolerance` | выигрыш не более 11% |
| Число объектов | почти линейно |
| Длинные текстовые свойства | существенно: 24 варианта названия у 900 объектов дали +1,3 МБ |
| Число вершин | заметно только на зумах 7+ |

Итоговые веса двух пилотных эпох: **573 КБ** (−2400, 825 объектов) и
**2,54 МБ** (117 год, 2253 объекта + 364 подписи акваторий + 9 морских
сражений). Обе укладываются в лимит GitHub Pages 100 МБ на файл с запасом
в десятки раз.
