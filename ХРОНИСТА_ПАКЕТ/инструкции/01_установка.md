# ШАГ 01. Установка

Ubuntu 26.04 LTS «Resolute Raccoon». Все версии пакетов ниже проверены по
Launchpad API именно для кодового имени `resolute`, а не взяты из общей
документации Ubuntu.

Занимает примерно 20 минут, из них 15 — скачивание дампа OHM.

---

## 1. Базовые пакеты

```bash
sudo apt update
sudo apt install -y python3 python3-pip git curl unzip openjdk-21-jdk
```

Проверка:

```bash
python3 --version      # ожидается 3.14.x
java -version          # ожидается openjdk 21.0.x
```

> **Почему именно 21, а не то, что ставится по умолчанию.** В Ubuntu 26.04
> по умолчанию идёт Java 25, а Planetiler v0.10.2 собран под Java 21+. На 25-й
> он работает, но если у вас окажется Java 11 (стоит в `openjdk-lts`), вы
> получите `UnsupportedClassVersionError` — я на это попал. Проверить все
> установленные JDK:
>
> ```bash
> python3 tools/extract_era.py doctor
> ```
>
> Команда перечислит найденные Java и скажет, какую выберет.

Если `java -version` показывает не 21:

```bash
ls -d /usr/lib/jvm/java-21-openjdk-*
export JAVA_HOME=$(ls -d /usr/lib/jvm/java-21-openjdk-* | head -1)
```

Чтобы не задавать каждый раз:

```bash
echo 'export JAVA_HOME=$(ls -d /usr/lib/jvm/java-21-openjdk-* | head -1)' >> ~/.bashrc
echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

## 2. Python-пакеты

```bash
sudo apt install -y python3-pip
pip install --break-system-packages pmtiles pyshp pyyaml
```

Проверка:

```bash
python3 -c "import pmtiles, shapefile, yaml; print('всё на месте')"
```

> **`--break-system-packages` — это нормально.** Ubuntu 26.04 запрещает
> ставить пакеты pip в системный Python, чтобы не сломать системные утилиты.
> Флаг разрешает установку. Альтернатива — виртуальное окружение:
>
> ```bash
> python3 -m venv ~/venv-chrono
> source ~/venv-chrono/bin/activate
> pip install pmtiles pyshp pyyaml
> ```
>
> Тогда перед каждой командой проекта нужен `source ~/venv-chrono/bin/activate`.
> С виртуальным окружением флаг `--break-system-packages` не нужен.

## 3. osmium-tool — для работы с дампом планеты

```bash
sudo apt install -y osmium-tool
osmium --version
```

Ожидается 1.19.0. Проверено наличие в `resolute`.

> **Зачем он.** Дамп планеты OHM весит 1,33 ГБ. Читать его целиком на каждый
> срез эпохи бессмысленно. `osmium tags-filter` вытаскивает из него только
> нужные объекты за один проход, и дальше всё работает с маленьким файлом.
>
> **Если osmium не ставится** — не блокирует работу: `extract_era.py` умеет
> запасной путь через Overpass API (`--overpass`). Он медленнее и зависит от
> доступности сервера OHM, но не требует дампа вовсе.

## 4. Planetiler — нарезка тайлов

Скачивается автоматически при первом запуске `make_tiles.py`. Вручную:

```bash
mkdir -p ~/history-demo/tools/planetiler
cd ~/history-demo/tools/planetiler
curl -L -o planetiler.jar \
  https://github.com/onthegomap/planetiler/releases/download/v0.10.2/planetiler.jar
ls -la planetiler.jar      # ожидается ~89 МБ
```

> **Не кладите `planetiler.jar` в git.** Файл весит 93 278 824 байта, а лимит
> GitHub — 100 МБ на файл: вы упрётесь в него почти сразу. В `.gitignore`:
>
> ```
> tools/planetiler/planetiler.jar
> tools/planetiler/classes/
> tools/planetiler/data/
> ```

Профиль `ChronoProfile.java` кладётся рядом:

```bash
cp ХРОНИСТА_ПАКЕТ/tools/ChronoProfile.java ~/history-demo/tools/planetiler/
```

## 5. QGIS — для ручной доработки

В репозитории Ubuntu 26.04 есть QGIS 3.40.15. Но официальная ветка с
длительной поддержкой новее — 3.44 LTS «Solothurn», и она поддерживает
кодовое имя `resolute` начиная с 3.44.9. Ставим официальную:

```bash
sudo mkdir -m755 -p /etc/apt/keyrings
sudo wget -O /etc/apt/keyrings/qgis-archive-keyring.gpg \
  https://download.qgis.org/downloads/qgis-archive-keyring.gpg
```

Отпечаток ключа (сверьте — это защита от подмены репозитория):

```bash
gpg --show-keys --with-fingerprint /etc/apt/keyrings/qgis-archive-keyring.gpg
```

Ожидается `2D7E 3441 A707 FDB3 E705  9441 D155 B8E6 A419 C5BE`, срок до
2027-08-08.

```bash
sudo tee /etc/apt/sources.list.d/qgis.sources > /dev/null <<'EOF'
Types: deb deb-src
URIs: https://qgis.org/ubuntu-ltr
Suites: resolute
Architectures: amd64
Components: main
Signed-By: /etc/apt/keyrings/qgis-archive-keyring.gpg
EOF

sudo apt update
sudo apt install -y qgis qgis-plugin-grass
qgis --version
```

> `ubuntu-ltr` — ветка длительной поддержки. Если хотите самую свежую,
> замените на `ubuntu` (там 4.2.x), но для рабочих данных LTS предсказуемее.

## 6. Дамп планеты OpenHistoricalMap

Это основной источник данных. Весит 1,33 ГБ, обновляется ежедневно.

```bash
mkdir -p ~/ohm && cd ~/ohm

# узнать имя свежего дампа
curl -s https://planet.openhistoricalmap.org/planet/state.txt
```

В ответе будет строка вида `261022_0000` — это дата и время дампа.

```bash
# подставьте то, что показала state.txt
curl -L -O https://planet.openhistoricalmap.org/planet/planet-261022_0000.osm.pbf
ls -la planet-*.osm.pbf      # ожидается ~1 325 983 523 байта
```

Проверка целостности:

```bash
osmium fileinfo planet-*.osm.pbf | head -20
```

> **★ Грабля, на которую я наступил.** `state.txt` отдаёт прямую ссылку на
> файл, и она указывает на `http://…s3.amazonaws.com/…`. Этот адрес
> возвращает **403 Forbidden**. Рабочий адрес — через
> `https://planet.openhistoricalmap.org/planet/planet-ДАТА.osm.pbf`.
> Проверено: HTTP/2 200, 1 325 983 523 байта.

Дальше укажите путь к дампу в `era.yml`:

```yaml
ohm_planet: "~/ohm/planet-261022_0000.osm.pbf"
```

## 7. Раскладка папок

```bash
mkdir -p ~/history-demo/{tools,deploy,maps/eras,maps/base,maps/poi,maps/_cache,tiles,out,public}

cp ХРОНИСТА_ПАКЕТ/tools/*.py   ~/history-demo/tools/
cp ХРОНИСТА_ПАКЕТ/tools/ChronoProfile.java ~/history-demo/tools/planetiler/
cp ХРОНИСТА_ПАКЕТ/deploy/*     ~/history-demo/deploy/
chmod +x ~/history-demo/tools/*.py

mkdir -p ~/history-demo/maps/eras/_template
cp ХРОНИСТА_ПАКЕТ/шаблоны/era.yml ~/history-demo/maps/eras/_template/era.yml
```

Должно получиться:

```
~/history-demo/
├── tools/            скрипты и ChronoProfile.java
├── deploy/           worker.js и wrangler.toml
├── maps/
│   ├── base/         подложка Natural Earth (шаг 02)
│   ├── eras/         эпохи, по папке на каждую
│   ├── poi/          деталь крупных городов (потом)
│   └── _cache/       кэш ответов Overpass — НЕ УДАЛЯТЬ
├── tiles/            готовые .pmtiles
├── out/              промежуточные GeoJSON
└── public/           то, что уходит в интернет (шаг 07)
```

> **`maps/_cache/` не удаляйте.** Там лежат ответы сервера OHM. Один ответ на
> мировую эпоху весит до 20 МБ и добывается минуты; с кэшем повторный запуск
> той же эпохи занимает 4 секунды вместо трёх минут. В git его класть не надо.

## 8. .gitignore

```bash
cat > ~/history-demo/.gitignore <<'EOF'
# Скачивается автоматически, в репозиторий не кладём (89 МБ, лимит GitHub 100 МБ)
tools/planetiler/planetiler.jar
tools/planetiler/classes/
tools/planetiler/data/

# Промежуточные результаты сборки — воспроизводятся из maps/
out/
public/
tiles/*.tmp

# Кэш ответов внешних серверов — воспроизводится, но долго
maps/_cache/

# Сырьё, скачанное для замеров
ne/
ne*.zip
hb_*.geojson
hb_index.json
wd_lookup.json

# Система
__pycache__/
*.pyc
.DS_Store
EOF
```

> Тайлы `tiles/*.pmtiles` в `.gitignore` **не** внесены намеренно: их вес
> небольшой (3–5 МБ на все эпохи), и в git их держать можно. Но если
> публикуете через R2 — в git они не нужны вовсе, и строку стоит добавить.
