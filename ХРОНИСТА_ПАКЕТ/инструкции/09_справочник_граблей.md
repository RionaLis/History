# ШАГ 09. Справочник граблей

Всё, на что я наступил при отладке, с замерами и причинами. Каждая запись —
это реальная поломка, а не теоретическая возможность. Порядок: сначала то, что
ломается тихо и стоит дороже всего.

## 1. Тихие ошибки: ничего не падает, но результат неверный

Самые опасные. Программа отработала без ошибок, а данные испорчены или
потеряны.

### 1.1 Рамка `bbox` отсекает нужные объекты

С рамкой 20,5,78,42 из среза −2400 выпадали **культура колоколовидных кубков**
(Испания) и **Аван**: их центроиды внутри рамки, но Overpass учитывает только
те узлы-участники, что попали в рамку. Пропусков было 8 вместо 6.

Для мировой карты `bbox` не задавайте вовсе. От мусора защищает фильтр
`testbed`, а не география.

### 1.2 Сравнение дат строками ломается на нашей эре до Христа

`"-2598" < "-2399"` — **истина** лексикографически. Поэтому Индская
цивилизация (−2598…−1899) молча исключалась из среза −2400.

Правильно — численное сравнение через `number()`:

```
(if: number(t["start_date"]) <= -2400 && (!is_tag("end_date") || number(t["end_date"]) >= -2400))
```

Документация OSM рекомендует строковое сравнение. Для дат до нашей эры оно
неверно.

### 1.3 `P31 = класс` не находит Чёрное море

Запрос `?item wdt:P31 wd:Q165` вернул 89 морей — **без Чёрного и без
Средиземного**. У Q166 `P31 = Q1973404` («внутреннее море»), а Q1973404 —
подкласс Q165. У Средиземного (Q4918) два P31: Q1973404 и Q166620.

Лечится обходом: `?item wdt:P31/wdt:P279* wd:Q165` → 142 моря, все нужные на
месте. **Ошибки при этом не было никакой** — запрос честно вернул 89 строк,
просто не те.

### 1.4 `LIMIT` молча выбрасывает важное

При `LIMIT 250` по классу «река» в файл попали Дон и Тибр, но НЕ попали
**Дунай, Тигр, Евфрат и Днепр**. SPARQL не гарантирует порядка строк.

При `LIMIT 1500` одним запросом по всем классам водоёмов 1500 мест съели реки
и озёра, и пропали Чёрное и Средиземное моря.

Лечится: запрос по классу отдельно + список нужных объектов, добытый **с
карты** (см. 1.5) + обязательный список `WATERS_ESSENTIAL`.

### 1.5 Список водоёмов надо брать С КАРТЫ, а не из Wikidata

Первая версия слоя названий строилась от запроса к Wikidata. Замер: на карте
117 года **412 уникальных Q-номеров** водоёмов, а в собранном списке нашлось
только **72** — 340 (83%) пропали. Среди пропавших Юкон, Цзиньша, Гань,
Уаикато, Сент-Клэр.

Причина: Natural Earth **уже несёт поле wikidata**, его имеют 550 из 600
объектов гидрографии (92%). Список нужных водоёмов уже лежит на вашей карте.

### 1.6 Служебная пометка занимала слот класса

При слиянии записей об одном объекте из разных источников в слот `class_ru`
писалось `REAL or cls`, то есть пометка «обязательный». Условие слияния
`if not merged[3]` после этого никогда не срабатывало, и настоящий класс из
запроса по классам отбрасывался.

Результат: Чёрное море и Дарданеллы остались с `class_ru=«обязательный»`, не
опознали себя как море и пролив, и подписи Понта Эвксинского и Геллеспонта не
создались. При этом запрос по классам их честно возвращал — проверено
отдельным запросом.

### 1.7 Догадка об историческом названии давала испанский вместо латыни

Первая версия выбирала «древнейшее на вид» имя по форме слова:

| Объект | Выдала | Что это на самом деле |
|---|---|---|
| Евфрат | Eufrates | испанский |
| Янцзы | Karayan Yangtze | тагальский |
| Иордан | Abhainn na hIordáine | ирландский |
| Тигр | Kali Tigris | индонезийский |
| Днепр | Dnièpre | французская транскрипция |

Всё это настоящие названия из Wikidata и всё бесполезно на карте римской
эпохи. Неверное имя хуже пустого: пустое вы заметите, а «Eufrates» уедет в
платный продукт.

Решение: поле остаётся пустым, рядом лежит список кандидатов, выбираете вы.

### 1.8 Сопоставление по имени находит тёзку с другим Q-номером

На карте объект лежал с `wikidata=Q40855` — это **РЕКА** Днепр, и в её
алиасах есть «Борисфен», «Borysthenes», «Βορυσθένης». А в списке обязательных
водоёмов был **Q48256** — это **ГОРОД** Днепр. Сопоставление по имени «Днепр»
сработало, уровень «вероятно», всё выглядело пристойно — но «Борисфен»
привязался бы к городу.

Добавлена отдельная пометка `hist_qid_clash`, и в отчёте такие случаи выводятся
выше всех остальных.

### 1.9 Поиск по названию отдаёт не то

На запрос «Тигр» Wikidata отдаёт: **1. Q19939 tiger — вид кошачьих**,
2. Q35591 Tigris — река, 3. Q151221 Tiger I — танк, 4. Q740762 Tiger — знак
зодиака.

На «Ван» первым приходит Q6593 = Vannes, коммуна во Франции. На «Гибралтар» —
город. Лечится разбором описаний по словам про воду и явными Q-номерами.

### 1.10 Q-номера по памяти — всегда неверные

Ошибок было столько, что пришлось завести отдельную команду `doctor`. Поймано:

| Написал по памяти | Оказалось | На самом деле |
|---|---|---|
| Q189574 «эпидемия» | запрос вернул 0 строк | **Q44512** |
| Q19822712 «морское сражение» | 0 строк | **Q1261499** |
| Q23397 «море» | это **озеро** | море **Q165** |
| Q35032 «пролив» | **православная церковь** | пролив **Q37901** |
| Q35509 «залив» | **пещера** | залив **Q1322134** |
| Q40880 «озеро» | коммуна **Таламона** | — |
| Q3313 «Чёрное море» | категория «Архитекторы Словакии» | **Q166** |
| Q127099 «озеро Ван» | чужой номер | **Q126307** |
| Q48256 «Днепр» | **город** | река **Q40855** |
| Q189058 «Гавгамелы» | **Целлинген в Баварии** | — |

Правило: любой Q-номер либо приходит из запроса, либо проверяется через
`tools/wd_lookup.py` / `wbsearchentities`. Никогда не пишите их из головы.

### 1.11 Валидатор проверял события по списку типов мест

`events.csv` содержал «битва», «персона», «катастрофа» — корректные значения
для событий. Валидатор сверял их со списком типов **мест** и выдал шесть
ошибок, заблокировав публикацию правильного файла.

Отдельно: 29 ошибок «kind «label» недопустим» на мировом срезе 117 года —
я добавлял новые типы в `extract_era.py`, а список допустимых в валидаторе
оставался старым.

И общее правило: **неизвестный `kind` — предупреждение, а не ошибка**. Сайт
берёт запасную иконку, объект рисуется.

### 1.12 Мёртвая константа создавала видимость работы

В `build_map.py` лежала `LAYERS = ("borders", "hydro", "places", "events")`,
которая нигде не использовалась: сборка перечисляла слои явными ветками. Из-за
этого в метаданных тайла `vector_layers` оказывался неполным, и у демо-эпохи
bc323 культуры лежали в данных, но не были объявлены — часть клиентов их из-за
этого не показывала.

Проверяйте готовый тайл, а не только лог сборки: сверяйте «объявлено» и
«реально лежит» (скрипт в шаге 06, §4).

## 2. Обрывы процесса и падения

### 2.1 OOM при запросе без фильтра по дате

Первый запрос `out geom` по рамке 20,5,78,42 **убил процесс, код 137**.
Причина: в этой рамке лежит 1 457 отношений `admin_level=2`, 42 116 отношений
`boundary=*` и 76 495 датированных элементов `place` — **за все эпохи сразу**.
Числовой фильтр по дате режет срез до 45 объектов.

Правило: тяжёлый запрос ограничивают **датой**, а не географией. Мировой срез
117 года на всю Землю проходит за 29 секунд и не падает.

### 2.2 `bbox` ненадёжен для отношений

Замерено. Один и тот же числовой фильтр при −2400:

| Запрос | Результат |
|---|---:|
| `relation["admin_level"="2"]` глобально | **10** |
| `relation(20,5,78,42)["admin_level"="2"]` | **2** |

Выпали Kulli (64.7 в.д.), Индская цивилизация (70.3), Элам (51.3), Дильмун
(49.2), Маган (55.8) — **все центроиды внутри рамки**. Зато остался Arzachena
(9.2 в.д.) — **вне рамки**. Причина: Overpass рассматривает только узлы-
участники, попавшие в рамку.

**Узлы и пути при этом работают нормально**: `node["place"]` глобально 197,
в рамке 43 — и это честные 43.

Правило: отношения запрашивать глобально, рамку применять только к узлам и
путям, а отношения фильтровать самому в Python.

### 2.3 Cloudflare отдаёт HTML с кодом 200

OHM Overpass и Wikidata SPARQL под нагрузкой возвращают **HTML-страницу с
кодом 200** и заголовком `Content-Type: application/json`. Падает как
`json.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`, что выглядит
как битый запрос, но им не является.

Усугубляет: **клиентский таймаут не отменяет запрос на сервере**. Сервер
продолжает его считать, и следующая попытка сразу упирается в лимит 2
одновременных запросов.

Лечение: 6 попыток с ожиданием 60/120/180/240/300 с, сохранение не-JSON-тел
на диск, распознавание Cloudflare-HTML, и **кэш успешных ответов** в
`maps/_cache/overpass/`. Один ответ на мировую эпоху весит до 20 МБ, но с ним
повторный запуск занимает 4 секунды вместо 29.

### 2.4 429 у Wikidata

Замерено: два SPARQL-запроса с паузой 8 секунд — второй уже 429. С паузой
75 секунд — проходит. В инструменте между SPARQL-запросами пауза 70 секунд,
внутри класса водоёмов — 20, на 429 до трёх повторов с ростом ожидания.

Обычный API (`wbgetentities`, `wbsearchentities`) к частоте гораздо мягче.
User-Agent обязателен: без него блокирует сразу.

### 2.5 `out geom` — это НЕ GeoJSON

Формат Overpass QL, и структура другая:

| Тип | Что в нём |
|---|---|
| `way` | `geometry` = **список `{"lat","lon"}`**, плюс `nodes` и `bounds` |
| `relation` | **нет `geometry` вообще**, только `members` с `type`/`ref`/`role`/`geometry`; роли `outer`, `inner`, `admin_centre`, `label` |
| `node` | **нет `geometry`**, только `lat`/`lon` на верхнем уровне |

Симптом: `AttributeError: 'list' object has no attribute 'get'` на
`g.get("coordinates")`, и **все 43 полигона отброшены** (0 сохранено), пока
мультиполигоны не начали собираться из `members` с ролями `outer`/`inner`.
После починки: 43/43 (Polygon 23, MultiPolygon 11, LineString 9).

## 3. Ошибки редактирования кода

Здесь они потому, что все три случились по-настоящему и все три тихие.

### 3.1 Замена текста стёрла заголовок функции

Замена блока, начинавшегося со `def find_overlaps(records):`, удалила
объявление и осиротила тело → `IndentationError`.

### 3.2 Старая версия функции осталась в файле и победила

После правки в файле оказались **обе** версии `normalize_geometry` и второй
`DATE_FILTER` — **после** новых. Python берёт последнее определение, поэтому
работала старая, битая версия.

Правило: после любой вставки через поиск-замену выполняйте

```bash
grep -n "^def " tools/extract_era.py | sort | uniq -d
python3 -c "import ast; ast.parse(open('tools/extract_era.py').read())"
```

Первая команда находит дубли определений, вторая — синтаксис.

### 3.3 Код из другой функции вставлен в первую

Блок с проверкой расхождения Q-номеров использовал переменную `props`, которая
есть только в `match_one()`, а вставлен был в `process_era()`, где та же
переменная называется `p`. Результат: `NameError: name 'props' is not defined`
при запуске.

Отдельная мелочь того же рода: вспомогательная функция правки текста была
объявлена с обязательным аргументом `label`, а дважды вызвана без него —
скрипт падал с `TypeError` **до записи файла**, и часть правок молча не
применялась. Проверяйте не только «синтаксис OK», но и что изменения реально
оказались в файле.

### 3.4 Индексация вместо поиска

Попытка заменить функцию через точный поиск строки не сработала из-за
расхождения пробелов, а проверка `assert` не была поставлена — и старая версия
осталась в файле. Там, где точная строка ненадёжна, вырезать по
`index()`/`rindex()` и проверять результат.

## 4. Внешние адреса и доступы

### 4.1 Дамп OHM

`https://planet.openhistoricalmap.org/planet/state.txt` отдаёт прямую ссылку
на файл, и она указывает на `http://…s3.amazonaws.com/…`, который возвращает
**403 Forbidden**.

Рабочий адрес — переписать на
`https://planet.openhistoricalmap.org/planet/planet-ДАТА.osm.pbf`.
Проверено: HTTP/2 200, 1 325 983 523 байта.

### 4.2 Natural Earth

`naturalearthdata.com/downloads/` возвращает **406 Not Acceptable** на
запросы из командной строки — защита от ботов. Рабочий хост —
**`naciscdn.org`**.

### 4.3 Pleiades

Хост — **`atlantides.org`**, а не `pleiades.stoa.org`:

```
https://atlantides.org/downloads/pleiades/json/pleiades-places-latest.json.gz   200, 135 788 869 Б
https://atlantides.org/downloads/pleiades/gis/pleiades_gis_data.zip              200,  35 671 706 Б
```

`pleiades.stoa.org/downloads` за JS-челленджем Anubis и для `curl` недоступен.

ZIP-версия документирована как проверенная в QGIS; Excel её разбирает
неверно.

### 4.4 `packages.ubuntu.com` и Launchpad

`packages.ubuntu.com` блокирует запросы (000/500). Наличие пакета в конкретном
релизе проверяется через Launchpad API:

```
https://api.launchpad.net/1.0/ubuntu/+archive/primary?ws.op=getPublishedSources&source_name=ИМЯ&exact_match=true&status=Published
```

и оставляются записи, у которых `distro_series_link` заканчивается на `resolute`.

**Отрицательные ответы этого метода ненадёжны**: `gdal-bin`, `python3-shapely`,
`python3-yaml`, `default-jdk` он показывал отсутствующими, хотя все они
поставляются. Положительные — надёжны.

### 4.5 OHM RDF / QLever

`osm2rdf.cs.uni-freiburg.de` отвечает 200, но
`ohm.qlever.cs.uni-freiburg.de` — 000, недоступен.

## 5. Данные OHM: что там есть и чего нет

### 5.1 Учебный полигон `testbed=yes`

**277 объектов** на всю базу (56 узлов, 220 путей, 1 отношение). Выглядят как
настоящие:

```
way/198794205   boundary=administrative  admin_level=9  start_date=0020-02-28
                name=«Admin 9 9999999 Admin 9»           testbed=yes
way/198794253   boundary=administrative  admin_level=3  start_date=0020-02-28
                name=«3 Admin 3 3333333 Admin 3»         testbed=yes
                name:ru=«OHM содержит исторические данные»
                + ещё 200 с лишним тегов name:* с переводом этой фразы
```

Дата `0020-02-28` честно попадает в срез 117 года. В мировом срезе их было
**34 из 2324** элементов (1,5%), и они заняли верх таблицы государств,
вытеснив настоящие провинции. После фильтра государств стало 75 вместо 85.

### 5.2 Для археологических культур отдельного тега НЕТ

`Bell Beaker culture`, `Arzachena culture`, `Kulli culture`, `小珠山文化`,
`Indus Valley Civilisation` — все лежат как `boundary=administrative` +
`admin_level=2`, неотличимо от государств вроде Элама или Кемета.

Слабые признаки: `border_type=kingdom` (один объект — Regnum Romanum),
`country=部落` («племя», на 小珠山文化), слова в `name`. Поэтому каждая
культура помечается как догадка, с указанием причины.

### 5.3 Перепись `boundary=*` — 82 539 отношений

administrative 78 757 · postal_code 1 516 · religious_administration **1 073** ·
judicial 414 · timezone 226 · protected_area 132 · census 80 ·
indigenous_administration **62** · place 59 · parcel 55 · national_park 41 ·
watershed 22 · statistical 19 · political 14 · ceremonial 13 · civil_parish 10 ·
local_authority 9 · civil 4 · border_zone 4 · military 3 · disputed 3 ·
parish 3 · aboriginal_lands 2 · maritime 2 · legal 1.

**Значений `route`, `trade_route`, `migration` нет вообще** — торговые пути и
миграции придётся рисовать вручную. Зато `religious_administration` (1 073) —
это реальные ареалы конфессий, и их можно тянуть тем же инструментом.

### 5.4 Качество дат

Замерено на мировом срезе 117 года:

| Файл | Пометка | Штук |
|---|---|---:|
| `hydro_117` (210 объектов) | `start_date:fixme = arbitrary` | **120 (57%)** |
| `hydro_117` | `fixme = arbitrary end_date` | 43 |
| `areas_117` | `start_date:fixme = arbitrary` | 34 |
| `points_117` | `fixme = Exact start and end dates` | 122 |
| `points_117` | `fixme = Location is estimation…` (Ohlone) | 57 |
| `points_117` | то же про Coast Miwok | 37 |

`arbitrary` означает буквально «произвольно»: дату поставили, чтобы объект
попадал в срезы, а не потому, что она известна. Такие объекты выглядят как
точные данные — это главная ловушка источника.

Отдельный пример подмены: `fixme = «These boundaries are at Baekje's peak in
375, not 42-562»` — ареал дан на момент наибольшего расширения, а не на дату
объекта. Для среза по году это подмена, и она помечается особо.

### 5.5 Мусор в поле wikidata у Natural Earth

У озера Неято и озера Ямбуто в поле `wikidata` стоит `-1`. Проверяется
регулярным выражением `^Q[1-9]\d*$`, отбрасывается вслух.

### 5.6 Морей в Natural Earth нет вовсе

Замерено на срезе 117 года: 645 объектов гидрографии — и **ни одного моря**.
Не нашлось Чёрного, Средиземного, Мраморного, Эгейского, Азовского,
Каспийского, Балтийского, Красного. В `lakes-50m.geojson` из 412 объектов
«Black» встречается один раз, «Mediterranean» — ноль.

Это не ошибка: Natural Earth — данные **суши**, море там получается пустым
местом между береговыми линиями. Подписи морей создаются из координат
Wikidata.

## 7. Сборка тайлов

### 7.1 Точки надо выпускать через `features.point()`

Проверено на Planetiler v0.10.2: на GeoJSON из ОДНОЙ точки
`anyGeometry()` не выдаёт ничего — в `.pmtiles` оказывается
`vector_layers: []` и ни одного тайла. Тот же файл через `point()` +
`setMinZoom(0)` даёт слой и тайл весом 102 байта.

Симптом очень тихий: сборка проходит без ошибок, вес файла выглядит
правдоподобно (полигоны-то на месте), а города и события на карте просто не
появляются. Так в bc323 пропали 2 города и 5 событий, а в bc2400 — все 196
городов.

### 7.2 Java

| Факт | |
|---|---|
| Planetiler v0.10.2 собран под Java **21+** | на Java 11 — `UnsupportedClassVersionError` |
| В Ubuntu 26.04 по умолчанию Java **25** | работает, но `openjdk-lts` тянет 11 |
| `javac` печатает «error while writing NullProfile: null» | **это не ошибка**, на результат не влияет |
| JDK в папке с точкой (`~/.jdk`) | исчезает: dot-каталоги исключены из снимка рабочей области |
| `maxzoom` | **единственный реальный рычаг веса**: ×2 на зум |
| `setPixelTolerance` | выигрыш не более 11% |

### 7.3 Длинные текстовые свойства в тайле

Три поля, нужных только для проверки в QGIS, давали **+1,3 МБ** к тайлу
(3,85 МБ вместо 2,54 МБ): список из 24 вариантов названия повторялся у
каждого из 900+ объектов в каждом тайле. `build_map.py` их выбрасывает.

Правило: в тайл идёт только то, что рисуется или показывается во всплывающем
тексте. Всё для проверки живёт в `geom/*.geojson` и в отчётах.

### 7.4 `pmtiles.Reader`

* **не** контекстный менеджер — нельзя `with`;
* принимает голый callable: `Reader(MmapSource(f))`;
* в заголовке есть `min_zoom`, `max_zoom`, `num_entries`, `tile_data_length`,
  `tile_type`, но **нет** `spec_version`;
* тайлы gzip'ованы, для поиска по содержимому нужен `gzip.decompress`.

## 8. Сервер и публикация

### 8.0 ★ Cloudflare из России не работает — и это меняет всю схему публикации

Самая дорогая грабля из всех, и я наступил на неё в документации: предложил
два бесплатных варианта на Cloudflare, не проверив доступность из России.

Факты, по официальным и независимым источникам, состояние на октябрь 2026:

| Дата | Что произошло |
|---|---|
| Ноябрь 2024 | Роскомнадзор рекомендовал отказаться от CDN Cloudflare из-за включённого по умолчанию TLS ECH; ЦМУ ССОП ГРЧЦ назвал его средством обхода ограничений |
| Февраль 2025 | Cloudflare принудительно внесён в реестр организаторов распространения информации (ОРИ). Представительства в РФ нет, требования невыполнимы |
| Апрель 2025 | РКН повторно рекомендовал отключить TLS ECH |
| **9 июня 2025** | Российские провайдеры начали обрезать соединения к сетям Cloudflare. Официальное заявление Cloudflare от 26.06.2025: «пользователи могут загрузить лишь первые **16 килобайт** содержимого сайта, что делает нормальную работу большинства ресурсов невозможной» |
| — | По внутренней статистике Cloudflare соединения обрываются после 10–14 пакетов — это уровень DPI, а не блокировка по IP |
| — | Трафик из России к серверам Cloudflare упал **более чем на 50%** (Cloudflare Radar) |
| — | Поддомен **`*.workers.dev` заблокирован РКН** — а это адрес, который выдаёт бесплатный Worker |
| Август 2026 | Начали ограничиваться DoH и DoT Google (8.8.8.8) и Cloudflare (1.1.1.1): TCP-сессия устанавливается, затем обрывается на TLS-рукопожатии |

**Почему это убивает именно карту, а не просто замедляет её.** PMTiles читает
файл диапазонами, и даже один запрос заголовка требует больше 16 КБ. Тайл
`era-bc2400.pmtiles` весит 573 КБ, `era-rome117.pmtiles` — 2,5 МБ. Обрезание
означает, что файл не скачается никогда: не «медленно», а «никак».

**Дополнительно:** карты российских банков при оплате Cloudflare отклоняются,
PayPal из России не проходит. То есть Workers Paid ($5/мес) оплатить тоже
нельзя.

**Проверить на своей машине:**

```bash
curl -s -o /dev/null -w "%{http_code} %{size_download} Б\n" --max-time 20 \
  https://welcome.developers.workers.dev/
```

Если `size_download` около 16 000 и страница не догрузилась — обрезание
действует и у вас.

**Что делать:** локальная сеть (0 ₽) или российский VPS (200–400 ₽/мес).
Подробно — в `08_РОССИЯ_хостинг_закон_платежи.md`.

**Смежный вывод про CDN.** Первая версия `make_public.py` подключала
`maplibre-gl.js` с `cdn.jsdelivr.net`, потому что у бесплатного Worker лимит
кода 1 МБ, а библиотека весит 1 056 837 байт. jsdelivr — не Cloudflare и
работает, но зависеть от зарубежного CDN, отдающего ОБЯЗАТЕЛЬНЫЙ файл, — это
точка отказа в стране, где такие точки отказа закрывают регулярно. Теперь
библиотека по умолчанию копируется в `public/`, и страница **не делает внешних
запросов вообще**. Флаг `--cdn` оставлен для зарубежной площадки.

Проверено: в отданном `index.html` нет ни одного `https://` на ресурсы
страницы; внешние ссылки остались только исходящие — на ваши статьи и на
Wikidata при клике на объект.

### 8.0а У российских S3 платный исходящий трафик — в отличие от R2

Это не грабля, а факт, который меняет выбор. У Cloudflare R2 исходящий трафик
бесплатен и неограничен — единственное такое предложение среди крупных облаков.
У российских объектных хранилищ трафик платный (цены октября 2026):

| Провайдер | Хранение | Исходящий трафик |
|---|---|---|
| Timeweb Cloud S3 | 1 ₽/ГБ·мес | 100 ГБ/мес бесплатно, дальше **1,3 ₽/ГБ** |
| Selectel S3 | от 2,33–2,57 ₽/ГБ·мес | **1,38 ₽/ГБ** |
| Yandex Object Storage | ~2,21–2,38 ₽/ГБ·мес | 100 ГБ бесплатно, дальше **1,68 ₽/ГБ** |
| VK Object Storage | 2,28 ₽/ГБ·мес | **1,31 ₽/ГБ** |

1 000 просмотров карты в месяц ≈ 2,6 ГБ — это 3–4 ₽, копейки. Но 100 000
просмотров — это 260 ГБ и **340–440 ₽/мес только за трафик**, тогда как VPS с
включённым трафиком стоит столько же целиком.

**Вывод: для раздачи тайлов российский VPS выгоднее российского S3.** S3 имеет
смысл, только если появятся сотни эпох и терабайты данных.

### 8.1 `python3 -m http.server` не годится

Отвечает **501** на OPTIONS и никогда не отдаёт **206** на Range. PMTiles
требует 206, карта не откроется. Используйте `tools/devserver.py`.

### 8.2 Сервер поднялся не из той папки

`devserver.py` брал корень от своего расположения (`__file__`) и игнорировал
аргументы, поэтому `make_public.py --serve` поднимал сервер на весь проект и
отдавал `maps/eras/*/qgis/gaps.md`, `polities.csv`, `era.yml` и кэш Overpass
кодом **200**. Заметно стало только по размеру `index.html`: 1004 байта вместо
19300.

Лечение: ключ `--root`, печать корня при запуске и предупреждение, если это не
`public/`.

### 8.3 Ключ в URL утекает через Referer

Страница обращается к CDN и Wikidata; по умолчанию браузер передаёт им полный
адрес страницы в Referer — вместе с `?k=СЕКРЕТ`, который добавляет
перехватчик `fetch`. Лечится `<meta name="referrer" content="no-referrer">`.

Сам ключ при этом берётся из **якоря** (`#k=…`): якорь браузер на сервер не
отправляет, поэтому ключ не оседает в журналах.

### 8.4 GitHub Pages

| Факт | |
|---|---|
| Лимит на файл | **100 МБ** — `planetiler.jar` (93 278 824 Б) почти упирается |
| Git LFS | **не отдаёт файлы на Pages** |
| Pages отдаёт любой файл любому | без пароля, это не настраивается |
| Проксировать Pages через бесплатный orange cloud | **нарушение правил Cloudflare**, кончается блокировкой |
| Требуется для PMTiles | хост должен отвечать **206** |

### 8.5 Кириллица в HTTP-заголовках

`curl` и Python падают с ошибкой кодека latin-1, если в заголовке кириллица.
Имена файлов в URL — только латиницей или percent-encoding.

## 9. Рабочая область и окружение

| Факт | Следствие |
|---|---|
| `out/`, `dist/`, `build/`, `node_modules/`, `.venv/`, `__pycache__/` и ещё ~20 имён исключены из сохраняемого снимка | `out/era-*.geojson` исчезает между сессиями — пересоберите через `build_map.py era --all` |
| Каталоги, начинающиеся с точки, исключены | `~/.jdk` пропал; держите JDK в `~/jdk21` |
| Снимок ограничен ~128 МБ или 10 000 файлов | **лишнее выбрасывается молча**. У меня так пропали `maps/eras/rome117/` целиком, `maps/base/rivers-50m.geojson`, кэш Overpass на 22 МБ и скачанная Java. Рабочая область разрослась до 289 МБ |
| Установленные pip-пакеты не сохраняются | `pmtiles`, `pyshp`, `pyyaml` переустанавливать |
| Фоновые процессы между сессиями умирают | сервер предпросмотра поднимать заново |
| `/tmp` не сохраняется | всё нужное — в рабочую папку |
| `xxd` отсутствует | использовать `od -An -c` |
| `grep -P '[\x{4e00}-\x{9fff}]'` | падает с «character code point value too large»; сканировать CJK через Python `re` |
| osmium в песочнице без root | не устанавливается, поэтому путь через дамп планеты здесь непроверяем |

> **Важно про последнюю таблицу.** Ограничение снимка в 128 МБ — особенность
> песочницы, в которой я работал. На вашей машине его нет. Но правило
> «держать тяжёлое и воспроизводимое в `.gitignore`» полезно и вам: `planetiler.jar`
> 89 МБ упрётся в лимит GitHub, а JDK и кэш в репозитории не нужны.

## 10. Мелочи, которые стоили времени

* **`variants` в `expected` — это список.** Наивное `str(v).lower()` давало
  `"['Kulli']"` вместо `"kulli"`, и сопоставление молча не срабатывало:
  13 реально отсутствующих объектов превращались в 8.
* **Лишняя запятая в заголовке CSV** (`maps/eras/_template/places.csv`) сдвинула
  все колонки.
* **`prep_base.py` нужны `.shp`, а не `.geojson`.** Natural Earth отдаёт
  shapefile.
* **Профиль Planetiler по умолчанию требует скачивания планеты.** Используйте
  `tags()`, а не `properties()`, и `overwriteOutput(Path)`.
* **Счётчик вершин на MultiPolygon** возвращал 0: обход не спускался в
  вложенные списки.
* **Не связывайте несколько медленных запросов к Overpass в одну команду.**
  Лимит 2 одновременных запроса, и один зависший тянет за собой все.
* **`部落` и `小珠山文化` в данных OHM — не порча кодировки**, а настоящие
  значения тегов.
* **Демо-эпоха bc323** собрана из `historical-basemaps` (GPL-3.0) и предназначена
  только как образец. В продукт её данные брать нельзя.
