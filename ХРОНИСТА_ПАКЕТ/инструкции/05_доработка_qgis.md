# ЧАСТЬ A. Сопоставление названий водоёмов

## A1. Ваше правило, как оно реализовано

```
Понт Эвксинский = Чёрное море = Q166
если не задана иная историческая геометрия — берётся Wikidata id
```

То есть сопоставление идёт **по Q-номеру**, а не по названию. Название —
только запасной путь, и он всегда помечается как сомнительный.

Почему по Q-номеру это работает: Natural Earth **уже несёт поле wikidata**,
и его имеют **550 из 600** базовых объектов гидрографии (92%). Причём это те
же самые номера Wikidata: Евфрат в Natural Earth — Q34589, ровно тот, который
`harvest_wikidata.py` нашёл по названию.

### Три уровня доверия

| Уровень | Что значит | Действие |
|---|---|---|
| **точно** | Q-номер совпал | применять можно |
| **вероятно** | Q-номера нет, совпало нормализованное имя | **проверить** |
| **не найдено** | ничего не совпало | ручная работа |

И отдельно, поверх всех трёх:

| **расхождение Q** | на карте один Q-номер, сопоставление нашло другой | **проверить обязательно** |

### Важно: «точно» не значит «имя известно»

Точное совпадение Q-номера означает, что известно, **что это за водоём**.
Оно НЕ означает, что известно, **как его звали в эту эпоху**: Wikidata хранит
названия плоским списком без дат. Поэтому поле `hist_name` остаётся пустым,
пока не заполнен `water_names_periods.csv`.

## A4. Почему моря пришлось создавать отдельно

**В Natural Earth морей нет вовсе.** Замерено на срезе 117 года: в слое
гидрографии 645 объектов (319 LineString, 182 MultiLineString, 143 Polygon,
1 MultiPolygon) — и ни одного моря. Не нашлось Чёрного, Средиземного,
Мраморного, Эгейского, Азовского, Каспийского, Балтийского, Красного.
В `maps/base/lakes-50m.geojson` из 412 объектов «Black» встречается один раз,
«Mediterranean» — ноль, «Caspian» и «Baltic» — ноль.

Это не ошибка, а устройство источника: Natural Earth — данные **суши**. Море
там получается пустым местом между береговыми линиями, отдельного полигона
«Чёрное море» в них нет и не будет.

Поэтому `match_waters.py` создаёт **точки-подписи**: координаты берутся из
P625 того же объекта Wikidata (у Чёрного моря это 34.26, 43.41), имя — из
вашего `water_names_periods.csv`. Полигон моря по-прежнему рисуется сам —
цветом воды базовой карты; подпись просто встаёт поверх него в нужном месте.

Свойство `hist_label = true` отличает такую подпись от объекта с реальной
геометрией. Подписи видны уже с `z_min = 3`: море занимает пол-экрана, и
прятать его имя до шестого зума смысла нет.

## A5. Что дописывается в свойства объекта

В `geom/hydro.geojson` у каждого сопоставленного объекта появляются:

| Поле | Что в нём | Идёт в тайл |
|---|---|---|
| `hist_name` | имя для этой эпохи | да |
| `hist_wikidata` | Q-номер, по которому совпало | да |
| `hist_match` | точно / вероятно | да |
| `hist_label` | `true`, если это подпись акватории | да |
| `hist_source` | ваш источник из `water_names_periods.csv` | да |
| `hist_qid_clash` | расхождение Q-номеров, если есть | да |
| `hist_candidates` | 4 первых варианта из Wikidata | да |
| `hist_names_all` | все варианты (до 24) | **нет** |
| `hist_modern_ru`, `hist_note` | служебные | **нет** |

Последние три в тайл не идут намеренно. Замерено: если их оставить,
`era-rome117.pmtiles` весит **3,85 МБ вместо 2,54 МБ** — больше, чем все
остальные слои вместе, потому что список из 24 названий повторяется у каждого
из 900+ объектов в каждом тайле. Полный список остаётся в
`geom/hydro.geojson` и в отчёте, где он и нужен.

## A6. Грабля: расхождение Q-номеров

Самый опасный тихий случай, и он случился на реальных данных.

На карте объект лежал с `wikidata=Q40855` — это **РЕКА** Днепр, и в её
алиасах есть «Борисфен», «Borysthenes», «Βορυσθένης», ровно то, что нужно.
А в моём списке обязательных водоёмов был **Q48256** — это **ГОРОД** Днепр.
Сопоставление по имени «Днепр» сработало, уровень «вероятно», всё выглядело
пристойно — но период «Борисфен» привязался бы к городу.

Поэтому добавлена отдельная проверка: если у объекта на карте Q-номер есть и
он НЕ равен тому, по которому совпало, ставится пометка
`hist_qid_clash = «Q40855 != Q48256»`, и в отчёте такой случай выводится
**выше всех остальных** — выше, чем «не найдено». Ненайденный объект просто
пуст, а расхождение означает, что данные противоречат друг другу.

Лечится так: проверьте оба номера через `tools/wd_lookup.py` или на
wikidata.org, и впишите верный — либо в `wikidata` объекта на карте, либо в
`water_names_periods.csv`.

задаётся один раз, по Q-номеру.

# ЧАСТЬ B. Доработка в QGIS

## B1. Открыть

```bash

```

Или вручную: QGIS → `Слой` → `Добавить слой` → `Добавить векторный слой` →
выбрать все `.geojson` из `maps/eras/rome117/qgis/`.

## B2. Что смотреть в первую очередь

Порядок определён ценой ошибки: чем раньше посмотрите, тем дешевле исправить.

**1. Чего не хватает.** Сравните карту со списком `expected` из `era.yml`
и с разделом «Не найдено из ожидаемого» в `gaps.md`. Для 117 года это десять
объектов: Иудея, Месопотамия, Кушанское царство, Сарматы, Албания Кавказская,
Иерусалим, Пергам, Эгнатиева дорога, Янтарный путь, Великий шёлковый путь.

**2. Расхождения Q-номеров.** В таблице названий водоёмов они идут первыми.

**3. Объекты с пометкой «проверить».** На мировом срезе 117 года их
**1627 из 1653**. Много — потому что помечается всё, включая «нет end_date»
и «дата произвольная». Смотрите поле `gap`: там причина словами.

**4. Пересечения по времени.** Раздел в `gaps.md`: объекты одного типа с
пересекающимися годами. Обычно это дубли или ошибка датировки.

## B3. Как включить отображение пометок

В панели слоёв → правый клик на слое → `Свойства` → `Символизация` →
`Категории` → значение выбрать `status`. Получите три категории:
`ok`, `needs-review`, `base`.

Либо `Правила` с условием:

```
"gap" IS NOT NULL AND "gap" != ''
```

— всё сомнительное станет, например, красной обводкой.

Для названий водоёмов полезно отдельное правило:

```
"hist_qid_clash" IS NOT NULL
```

## B4. Что править прямо в QGIS

| Что | Как |
|---|---|
| `kind` объекта | Открыть таблицу атрибутов, изменить значение |
| Даты `start` / `end` | Там же |
| `name_ru` | Там же |
| `wikidata` | Там же — и расхождение Q-номеров лечится именно так |
| Геометрию границ | `Переключить редактирование` → правка узлов |
| Нарисовать недостающее | `Создать слой` → `Новый временный слой` → оцифровка |

После правок: `Сохранить изменения` и экспортировать слой обратно в
`maps/eras/rome117/geom/` как GeoJSON.

> **QGIS сохраняет GeoJSON по-разному** в зависимости от версии и настроек
> экспорта. `build_map.py` это учитывает: функция `_read_geom_file` умеет и
> `FeatureCollection`, и одиночный `Feature`, и массив геометрий. Но если
> после экспорта слой перестал читаться — проверьте, что файл начинается с
> `{"type": "FeatureCollection"`.

## B5. Допустимые значения `kind`

Свои для каждого файла. Один общий список здесь был ошибкой: я добавлял в
`extract_era.py` новые типы, а валидатор продолжал сверять со старым списком

недопустим»** на совершенно корректных данных — регионах Августовой Италии,

**`polities.csv`** (полигоны):

| kind | Что это |
|---|---|
| `state`, `empire`, `kingdom`, `city_state`, `republic` | государства |
| `culture`, `civilization`, `tribe`, `nomads`, `confederation` | народы и культуры: ареал, а не граница |
| `label` | крупная единица, заданная в OHM точкой: ареала нет, рисуется подписью. Так лежат Парфия (Q1986139), Дакия (Q971609), регионы Августовой Италии, Теотиуакан (Q172613), Moche (Q208188) |
| `place` | прочая территория с названием |
| `unknown` | не определилось — решить вручную |

**`places.csv`** (точки): `city`, `town`, `settlement`, `village`, `hamlet`,
`monument`, `place`, `label`, `unknown`.

**`routes.csv`** (линии): `route`, `road`, `trade_route`, `sea_route`,
`migration`, `unknown`.

**`events.csv`** — словарь задаёте вы сами, список открытый:

```
битва  сражение  осада  персона  рождение  смерть  катастрофа  извержение
землетрясение  эпидемия  изобретение  открытие  договор  мир  восстание
мятеж  реформа  коронация  основание  падение  поход  миграция  собор  событие
```

Русские значения — норма: в демо-эпохе `bc323` уже лежат «битва», «персона»
и «катастрофа», и это правильно.

> **Неизвестный `kind` — предупреждение, а не ошибка.** Сначала я сделал это
> ошибкой, и валидатор заблокировал публикацию шести совершенно корректных
> событий только потому, что я проверял `events.csv` по списку типов **мест**.
> Сайт при неизвестном `kind` берёт запасную иконку — объект нарисуется.

## B6. Два правила, которые стоит запомнить

**Точка не может быть границей.** Реальный случай: Londinium (Q927198) пришёл
из OHM узлом `place=city`, но с тегом `boundary=administrative`. Проверка тега
стояла выше проверки типа геометрии — город попал в границы, файла геометрии
для точки не создалось, сборка печатала «Londinium: геометрия не найдена»,
а валидатор блокировал публикацию. Теперь **тип геометрии проверяется раньше
тега**.

**Дорога без линии — не дорога.** Если геометрию отношения не удалось собрать
и остался центроид, `kind=route` автоматически понижается до `label`, а в
`note` пишется причина. Иначе валидатор справедливо ругался на «route» в
точечном файле.
