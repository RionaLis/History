# ШАГ 04. Слои из Wikidata: морские сражения, эпидемии, названия водоёмов

Трёх нужных вам слоёв в OpenHistoricalMap **нет вовсе**. Замерено:

* морские сражения — в OHM нет класса «морская битва»;
* эпидемии — ни одного объекта;
* исторические названия водоёмов — из 210 именованных водоёмов с датой только
  у **одного** есть `name:ru` и у **одного** `old_name`/`alt_name`.

Wikidata закрывает первые два почти полностью, третий — наполовину.
Лицензия Wikidata — **CC0**, общественное достояние: можно в платном продукте
без ограничений и без атрибуции.

Инструмент: `tools/harvest_wikidata.py`.

### Почему отдельный слой, а не `kind` внутри событий

У морского боя другая иконка, другая подпись и другая семантика: он привязан
к акватории, а не к суше, и его хочется показывать и скрывать независимо от
сухопутных битв.

У вас в репозитории в `assets/map/data/events.geojson` уже лежат **20 точек
с `kind=битва`** — это сухопутные. Они останутся в слое `events`.

## 2. Эпидемии

```bash
python3 tools/harvest_wikidata.py epidemics rome117
```

### Почему этот слой устроен не так, как остальные

Первая версия строила буфер-окружность вокруг координат из P625 и считала
радиус от длительности. **Она не работала**, и причина фундаментальная:
у крупнейших пандемий координат в Wikidata **нет вообще**.

Замерено на Чёрной смерти (**Q42005**): P625 отсутствует, зато есть
**P276 «location» с четырьмя регионами** — Q48 Азия, Q46 Европа, Q27381,
Q18869 — и даты P580/P582 = 1346…1352, и P1120 = 75 000 000 жертв.
У Юстиниановой чумы (**Q821711**) нет **ни координат, ни регионов**, только
год 541.

Буфер вокруг пустоты — это ноль объектов на карте. Поэтому сделано иначе и в
два файла:

| Файл | Что в нём |
|---|---|
| `geom/epidemics.geojson` | точки: центр эпидемии (если есть) **плюс центр каждого поражённого региона**, с датами и числом жертв. Слой рисуется как подписи |
| `epidemics_regions.auto.csv` | заготовка: строка на пару «эпидемия × регион», с пустыми колонками `match` и `note` |

Контур эпидемии вы рисуете в QGIS сами. Автоматически сопоставить «Азию» из
Wikidata с вашим полигоном Азии нельзя: у вас границы свои, нарисованные по
источникам, а у Wikidata регион — понятие без геометрии.

### Проверка на реальной эпохе

Тестовый срез 1350 года дал у Чёрной смерти **8 поражённых регионов с
координатами**:

| Регион | Координаты |
|---|---|
| Европа | 9.14, 48.69 |
| Азия | 87.33, 43.68 |
| Кавказ | 44.5, 42.75 |
| Северная Африка | 9.68, 30.44 |
| Азербайджан | 47.7, 40.3 |
| Грузия | 44.0, 42.0 |
| Армения | 44.95, 40.38 |
| Великое княжество Московское | — |

Плюс 75 000 000 жертв при каждой точке и период 1346…1352.

**Срез 117 года н. э. дал ноль эпидемий.** Это не поломка, а честный
результат: крупных пандемий тогда не было, Антонинова чума начнётся в 165 году.
Проверка на 1350 годе убеждает, что запрос работает.

Слой в тайлах называется **`epidemics`**.

## 3. Названия водоёмов

```bash
python3 tools/harvest_wikidata.py waters rome117
```

Прогон занимает **около четырёх минут** — там шесть SPARQL-запросов с паузами
и десяток пачек обычного API. Это нормально, не прерывайте.

Реальный вывод:

```
    с карты этой эпохи: 411 уникальных Q-номеров (551 упоминаний)
      ! в Natural Earth попадается мусор в поле wikidata — 2 шт., отброшено:
          wikidata=«-1» у «озеро Неято» — не похоже на Q-номер
      названия получены у 408 из 411
    море     (wd:Q165, с обходом подклассов) → 145
    пролив   (wd:Q37901, с обходом подклассов) → 120
    залив    (wd:Q1322134, с обходом подклассов) → 80
    океан    (wd:Q9430, с обходом подклассов) → 20
    река     (wd:Q4022) → 250
    озеро    (wd:Q23397) → 150
    всего 1173 водоёмов
    добираю 51 обязательных водоёмов по названию…
      найдено 51, не найдено 0
    без повторов: 1034  (с карты 708, с координатами 991)
    контроль пройден: Чёрное, Средиземное, Мраморное и Эгейское моря в слое
```

### Три источника в одном файле

| Происхождение | Что это | Зачем |
|---|---|---|
| **с карты** | Q-номера объектов, которые реально лежат в вашем `geom/hydro.geojson` | гарантия, что название найдётся для каждого объекта карты |
| **по классам** | моря, проливы, заливы, океаны, реки, озёра из Wikidata | даёт объекты, которых на карте пока нет, и полный набор вариантов имён |
| **обязательные** | список `WATERS_ESSENTIAL` в начале файла | страховка: важные водоёмы не теряются из-за `LIMIT` |

### Почему список берётся С КАРТЫ

Первая версия строилась только от запроса «дай мне моря, проливы, реки…» с
`LIMIT` на каждый класс. Замер показал, что так теряется почти всё: на карте
117 года было **412 уникальных Q-номеров** водоёмов, а в собранном списке
нашлось только **72** из них — **340 (83%) пропали**. Среди пропавших Юкон,
Цзиньша, Гань, Уаикато, Сент-Клэр — всё это настоящие реки, просто их
вытеснили другие реки в пределах `LIMIT`.

Причина в том, что Natural Earth **уже несёт поле wikidata**: его имеют
550 из 600 базовых объектов гидрографии (92%). Значит список нужных водоёмов
уже лежит на вашей карте, и запрашивать Wikidata надо по нему.

### Три грабли этого слоя

**1. `P31 = класс` НЕ НАХОДИТ ЧЁРНОЕ МОРЕ.** Запрос `?item wdt:P31 wd:Q165`
вернул 89 морей — **без Чёрного и без Средиземного**, двух главных морей
античной карты. Причина: у Q166 `P31 = Q1973404`, а Q1973404 — это
«adjacent sea / внутреннее море», которое само подкласс Q165 (`P279 = Q165`).
У Средиземного (Q4918) вообще два P31: Q1973404 и Q166620.

Лечится обходом по иерархии: `?item wdt:P31/wdt:P279* wd:Q165` → **142 моря
с русской подписью, все нужные на месте, все с координатами**. Проверено
отдельным запросом. Ошибки при этом не было никакой — запрос честно вернул
89 строк, просто не те.

**2. `LIMIT` молча выбрасывает важное.** При `LIMIT 250` по классу «река»
в файл попали Дон и Тибр, но НЕ попали **Дунай, Тигр, Евфрат и Днепр**.
SPARQL не гарантирует порядка строк. Лечится этапом «с карты» и списком
`WATERS_ESSENTIAL`.

**3. Поиск по названию даёт тёзок.** На запрос «Тигр» Wikidata отдаёт:

```
1. Q19939   tiger      — «species of big cat»
2. Q35591   Tigris     — «river flowing from Turkey through Iraq and Syria»
3. Q151221  Tiger I    — танк
4. Q740762  Tiger      — знак зодиака
```

Брать первый результат значит положить в слой исторических названий рек
большого кота. На «Ван» первым приходит Q6593 = Vannes, коммуна во Франции.
На «Гибралтар» — город. Лечится разбором описаний по словам про воду
(`WATER_HINTS`) и явными Q-номерами (`WATERS_BY_QID`).

## 5. Про лимиты Wikidata

SPARQL-эндпоинт отдаёт **429 Too Many Requests**, если слать подряд. Замерено
на себе: два запроса с паузой 8 секунд — второй уже 429; с паузой 75 секунд —
проходит. В инструменте между SPARQL-запросами пауза 70 секунд, внутри класса
водоёмов — 20, на 429 делается до трёх повторов с ростом ожидания.

Wikidata под нагрузкой отдаёт HTML-страницу с кодом 200 — та же ловушка, что
у Overpass OHM. Обрабатывается так же: не-JSON-тело распознаётся, ждём,
повторяем.

**User-Agent обязателен**: без него Wikidata блокирует запрос сразу. В начале
`harvest_wikidata.py` есть константа `UA` — подставьте туда свой контакт, это
снижает шанс блокировки.

Обычный API (`wbgetentities`, `wbsearchentities`) к частоте гораздо мягче,
поэтому названия забираются пачками по 50 с паузой 2 секунды.
