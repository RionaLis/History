# Куликово поле — прототип базы знаний

Рабочий прототип с четырьмя уровнями доступа, личным кабинетом, заметками
и заглушкой оплаты. Оплата не подключена: тарифы создают запись о покупке —
ту же самую, что потом будет создавать платёжный сервис.

## Запуск

```bash
cd site
node server.js
```

Открыть `http://localhost:3000`. Зависимостей нет — нужен только Node.

## Что есть

| Раздел | Что внутри |
|---|---|
| `/` | главная, счётчики зависят от уровня |
| `/articles` | 6 статей, фильтры по теме и типу |
| `/article/<id>` | статья: превью, текст, видео, доп. поля, заметки к абзацам; у статей о сущностях — карточка Wikidata с картинкой и ссылкой «Подробнее» |
| `/videos` | каталог 8 видео, сортировка по дате и названию, поиск |
| `/search` | поиск по статьям (всем) и по видео (с уровня 1) |
| `/qa` | вопросы и неполадки, форма обращения, история своих обращений |
| `/levels` | сравнение уровней |
| `/register` | демо-регистрация (профиль) |
| `/account` | **личный кабинет**: разрешения, покупки, заметки, промокод |
| `/subscribe` | **тарифы и заглушка оплаты** |
| `/notes` | **мои заметки**: отдельные и к абзацам, экспорт в Markdown |
| `/prototype` | как это устроено, с реальными фрагментами кода |

## Как тестировать

Полоса сверху — переключатель уровней 0–3 (демо-инструмент). Основные сценарии:

1. **Уровни.** Откройте `/article/hod-bitvy` и пройдите 0 → 1 → 2: превью
   с оглавлением → полный текст → плеер и панель связей.
2. **Два типа статей.** `/article/Q210354` (Куликовская битва) — карточка
   Wikidata видна всем бесплатно. `/article/istochniki` — авторская: своё
   вступление и оглавление. Сравните превью.
3. **Заметки.** Уровень 3 → `/notes` → создайте отдельную заметку. Затем
   откройте статью, наведите на абзац, нажмите «＋» слева — появится форма
   заметки с подставленной цитатой.
4. **Понижение уровня.** Создайте заметки на уровне 3, переключитесь на 2:
   создание закрыто, старые заметки читаются и выгружаются.
5. **Заглушка оплаты.** `/subscribe` → «Оформить на месяц» → `/account`:
   появится запись о покупке и разрешение с источником «покупка», а
   демо-переключение снимется.
6. **Точечный доступ.** Уровень 0 → `/account` → код `KULIKOVO7` открывает
   статью об источниках. Код `NOTES30` даёт уровень 3 на 30 дней.
7. **Главная проверка.** На уровне 0 откройте закрытую статью и посмотрите
   исходный код (Ctrl+U): текста там нет. Сервер его не отправил.

## Где подключается настоящая оплата

Три места, и ни одного в страницах:

1. `lib/session.js` → `subscribeStub()` — сегодня её зовёт форма, завтра —
   обработчик события платёжного сервиса (`/webhook` с проверкой подписи).
2. `lib/entitlements.js` → `grantLevel(record, level, 'purchase', {to})` —
   создаёт разрешение. Источник `'purchase'` уже поддержан везде.
3. `lib/store.js` — сейчас пишет JSON, потом будет писать в базу данных.

Страницы, проверка доступа, кабинет и заметки при этом не меняются.

## Устройство

```
server.js              маршруты
lib/pages.js           страницы
lib/access.js          матрица доступа (POINTS) и функция can()
lib/entitlements.js    разрешения, квоты, фазы (FLAGS)
lib/session.js         кто пришёл; здесь точка подключения оплаты
lib/notes.js           заметки: квоты, якоря, проверка изменений, экспорт
lib/store.js           хранилище (JSON за интерфейсом)
lib/md.js              рендер Markdown, блоки для якорей заметок
content/articles/      статьи в Markdown + снимки Wikidata
content/_templates/    шаблоны для заполнения статей и видео
public/img/            картинки для карточек сущностей
data/state.json        демо-данные: разрешения, покупки, заметки
```

Демо-данные живут в `data/state.json`. Чтобы начать с чистого листа,
удалите эту папку при остановленном сервере (или нажмите «Сбросить демо»
в кабинете).

## Почему состояние живёт в адресе

В предпросмотре сайт открывается внутри песочницы: cookie не сохраняются,
а обычная отправка форм блокируется. Поэтому прототип устроен так:

- идентификатор сессии передаётся в адресе — `?u=…`, и сервер сам проставляет
  его во все внутренние ссылки и формы;
- переключатель уровней сделан ссылками, а не формой;
- формы дополнительно отправляются через `fetch` (скрипт `public/app.js`),
  чтобы работать там, где обычная отправка запрещена.

**Это приём только для прототипа.** В настоящей версии идентификатор сессии
нельзя держать в адресе: он попадает в историю, закладки и заголовок Referer.
Там будет обычная сессия на сервере в защищённой cookie. Всё остальное —
проверка доступа, разрешения, кабинет — останется тем же.

## Что в прототипе ненастоящее

- **Оплата** — заглушка: запись о покупке создаётся формой, а не сервисом.
- **Аккаунты** — идентификатор в cookie, пароля нет. В реальной версии —
  сессия на сервере и подтверждение почты.
- **Хранилище** — JSON-файл вместо базы данных.
- **Видео** — чужие публичные ролики как заглушки; метаданные условные.
- **Заметки** — без редактирования (только создание и удаление), без
  конспектов.
- **Обращения** — хранятся локально, никуда не отправляются.

## Ограничение предпросмотра

Плеер загружается по нажатию. Внутри предпросмотра Arena внешние сайты
недоступны, поэтому iframe останется пустым — это ограничение предпросмотра,
а не сайта. Ссылка «Открыть на YouTube» работает всегда, а в обычном браузере
плеер запускается нормально.
