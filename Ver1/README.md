# Adam's History — интерактивный исторический атлас

Русскоязычный статический сайт для GitHub Pages. Хронология охватывает **12 000 год до н. э. — 1900 год н. э.** Данные редактируются в Markdown-заметках с YAML frontmatter, поэтому папку `content/` можно открыть в Obsidian и версионировать вместе с сайтом.

## Возможности

- Нелинейная временная карта общей шириной около четырёх экранов на первом масштабе. Более поздние века получили больше места; горизонтальная прокрутка охватывает весь диапазон и не исчезает при увеличении.
- Масштабирование и перемещение фокуса, переход к эпохе или периоду, ручной ввод начальной и конечной дат. Отрицательные числа обозначают годы до н. э.
- Географически упорядоченные линии регионов; фильтр одного или нескольких регионов.
- На обзорном масштабе видны только основные события; можно выбрать «Основные», «Региональные» или «Все события».
- Отдельные ветви: государства, правители, наука и открытия, искусство.
- Подсказка с кратким описанием при наведении; щелчок по событию, правителю, персоне или карточке эпохи открывает полную страницу.
- Нижняя шкала лет жизни персон окрашена **только по государству/политическому контексту**.
- Поиск, hash-маршруты, статьи в Markdown, адаптивная верстка. Серверная часть и внешние библиотеки не нужны.

## Запуск локально

Сайт загружает индекс через `fetch`, поэтому открывайте его через HTTP-сервер, а не напрямую как `file://`:

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000`.

## Публикация на GitHub Pages

1. Загрузите в корень репозитория `index.html`, `styles.css`, `app.js`, `load-data.js`, `content-index.json`, `favicon.svg`, `.nojekyll`, папку `content/` и папку `scripts/`.
2. Откройте **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`.
4. Сохраните настройки. Относительные адреса ресурсов позволяют размещать проект как в корне домена, так и в подпапке репозитория.

GitHub Pages отдаёт готовые статические файлы. Python нужен только редактору, чтобы пересобрать индекс после изменения заметок; запускать Python на опубликованном сайте не нужно. Маршруты статей имеют вид `#event/ID`, `#ruler/ID`, `#person/ID` и `#era/ID`.

## Редактирование в Obsidian

1. Откройте `content/` как отдельный vault Obsidian либо откройте весь репозиторий.
2. Включите встроенный плагин **Templates** и укажите папку шаблонов `content/templates/` (по желанию). Шаблоны: `event.md`, `person.md`, `ruler.md`, `state-track.md`, `thematic-track.md`, `era.md`.
3. Создайте заметку по шаблону в соответствующей папке: `content/events/states/`, `content/events/science/`, `content/events/arts/`, `content/people/`, `content/rulers/`, `content/tracks/…` или `content/eras/`.
4. Заполните YAML frontmatter в начале заметки, а статью пишите ниже закрывающей строки `---` обычным Markdown. Краткий `summary` показывается в подсказке на шкале; полная заметка открывается по щелчку.
5. После редактирования в корне репозитория выполните:

   ```bash
   python3 scripts/build_content.py
   ```

6. Проверьте сайт и сохраните в Git **и Markdown-заметки, и новый `content-index.json`**. Индекс — генерируемый файл, не редактируйте его вручную.

Скрипт использует только стандартную библиотеку Python. Он понимает YAML frontmatter со скалярными значениями, JSON-подобными массивами/объектами, списками вида `- элемент` и блочными строками `|`/`>`; JSON-формат YAML-фрагментов используется в шаблонах для удобства разбора без PyYAML. На страницах отображаются заголовки, списки, цитаты, таблицы, блоки кода, выделение и ссылки; сырой HTML намеренно не исполняется.

### Пример заметки события

```yaml
---
type: "event"
id: "sample-event"
title: "Название события"
branch: "states"
track: "mediterranean"
year: 1453
level: "major"
display: "state"
summary: "Краткая справка на одно-два предложения для подсказки."
tags: ["регион", "политика"]
---

## Контекст

Полная статья в Markdown. Добавьте значение события, последствия и ссылки на источники.
```

### Поля и допустимые значения

- Событие: `branch` — `states`, `science` или `arts`; `track` — точный `id` линии из `content/tracks/`; `year` — целое число; `level` — `major`, `regional` или `minor`.
- `display` задаёт форму маркера: `society`, `city`, `state`, `monument`, `law`, `war`, `politics`, `trade`, `religion`, `contact`, `industry`, `disaster`, `treaty`, `invention`, `discovery`, `text`, `painting`, `music` или `event`.
- Персона: `born`, `died`, `group`, `activityKey`, `activityLabel`, `polity`, `polityKey`, `summary`; `group` должен совпадать с ID одной из групп в `content/settings.md`. Палитра задаётся ключом `polityKey`.
- Правитель: `start`, `end`, `track`, `name`, `title`, `summary`; `track` должен совпадать с ID заметки линии правителей.
- Эпоха: `from`, `to`, `name`, `short`, `color`, `summary`.
- Новым событиям, персонам, линиям и эпохам нужны уникальные латинские ID, подходящие для URL и имени файла, например `battle-of-example`.

Для добавления линии используйте нужный шаблон и обновите порядок регионов в `content/settings.md`, если линия должна участвовать в географической последовательности. Периоды государственной линии указываются в поле `periods`. Персональные ветви деятельности уже разделены в навигации; поэтому менять цвет людей по роду занятий нельзя — он закреплён за политическим контекстом.

## Сборка и проверка

```bash
python3 scripts/build_content.py
node --check app.js
```

Скрипт проверяет, среди прочего, обязательные поля, уникальность ID, уровни и виды маркеров, привязку событий и правителей к линиям, интервалы жизни и правления, а также группы персон. При любой ошибке он завершится с сообщением о файле и причине.

## Структура

- `index.html` — оболочка сайта;
- `load-data.js` — загрузка JSON-индекса и интерфейса;
- `app.js` — временная карта, навигация, поиск и статьи;
- `styles.css` — оформление;
- `content/` — исходные редактируемые Markdown-заметки с YAML frontmatter;
- `content/templates/` — шаблоны для Obsidian;
- `content/settings.md` — общий диапазон, порядок линий, группы персон и палитра государств;
- `content-index.json` — сгенерированный индекс для браузера;
- `scripts/build_content.py` — сборщик индекса без сторонних зависимостей;
- `favicon.svg`, `.nojekyll` — ресурсы GitHub Pages.

## Редакционное замечание

Содержимое — стартовая редакционная выборка, а не исчерпывающая база мировой истории. Датировки и описания требуют источниковой и исторической проверки перед образовательным или публичным использованием. Добавляйте библиографию и уточняйте спорные даты в самих Markdown-заметках.
